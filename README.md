# ALPHA — ИИ-помощник для предпринимателей «Альфа-Курса»

**Хакатон · Трек 2 — ИИ-помощник для предпринимателей в Telegram**

ALPHA — Telegram-бот и Telegram Mini App для пользователей образовательной платформы «Альфа-Курс». Помощник отвечает на вопросы по базе знаний, уточняет недостаточно ясные запросы, учитывает профиль предпринимателя, рекомендует учебные материалы и создаёт разовые и повторяющиеся напоминания.

## 1. Назначение решения

Предпринимателю приходится самостоятельно искать ответы на вопросы о запуске и развитии бизнеса, выбирать полезные образовательные материалы и следить за важными задачами. ALPHA объединяет эти сценарии в одном интерфейсе Telegram.

**Целевая аудитория:** люди, планирующие открыть своё дело, начинающие и действующие предприниматели.

**Основной сценарий:**
1. Пользователь запускает бота командой /start.
2. Сообщает стадию бизнеса, сферу, налоговый режим, опыт и цель.
3. Задаёт вопрос, просит подобрать материалы или создать напоминание.
4. Система анализирует запрос и ищет сведения в базе знаний и каталоге.
5. Помощник формирует ответ по найденному контексту. Если информации недостаточно, сообщает об этом или задаёт уточняющий вопрос.
6. Пользователь получает подходящие ссылки и может вернуться к обучению через материалы и напоминания.

## 2. Возможности

### Консультации по базе знаний
- Принимает вопросы на естественном русском языке.
- Анализирует намерение пользователя и формирует поисковый запрос.
- Ищет релевантные фрагменты базы знаний PostgreSQL.
- Передаёт найденный контекст языковой модели для подготовки ответа.
- При недостатке подтверждающей информации сообщает, что точного ответа в базе нет.

### Уточнение и персонализация
- Сохраняет стадию бизнеса, сферу, налоговый режим, опыт, цель и часовой пояс.
- Учитывает профиль и историю диалога при последующих консультациях и подборе материалов.
- Может запросить недостающую информацию, если без неё нельзя дать содержательный ответ.

### Рекомендации материалов
- Ищет материалы каталога по запросу пользователя.
- Ранжирует результаты с учётом релевантности и профиля.
- Фильтрует закрытые и нерекомендуемые материалы.
- Бесплатные материалы показывает только при наличии подтверждённой ссылки.
- Для платных материалов использует предоставленную ссылку на покупку; закрытое содержание не раскрывает.

### Напоминания
- Создаёт разовые и повторяющиеся напоминания.
- Поддерживает периодичность, предусмотренную приложением: ежедневно, еженедельно, ежемесячно, ежегодно и через заданное число дней.
- Учитывает часовой пояс пользователя.
- Позволяет просматривать, отключать и изменять напоминания в поддерживаемых сценариях.
- Налоговые напоминания носят информационный характер: даты необходимо сверять с актуальными официальными данными ФНС.

### Telegram Mini App
- Веб-интерфейс для общения с помощником, работы с профилем, материалами и напоминаниями.
- Пользовательские API защищены проверкой подписи Telegram Mini Apps initData.

## 3. Архитектура

Проект состоит из Telegram-бота, HTTP API, веб-клиента Mini App, модулей анализа и диалога, поиска и рекомендаций, LLM-интеграции и PostgreSQL.

~~~text
Пользователь
   |
   +--------------------------+
   |                          |
Telegram Bot             Telegram Mini App
   |                          |
   |                       FastAPI
   |                          |
   +-------- Диалог / API -----+
                 |
              Анализ
                 |
        +--------+---------+
        |                  |
   Поиск по KB        Поиск каталога
        |                  |
   Фрагменты базы      Ранжирование
        |                  |
        +--------+---------+
                 |
              LLM API
                 |
         Ответ / материалы
                 |
             Пользователь

PostgreSQL: профили, история, события, напоминания,
каталог материалов и база знаний.
Фоновый процесс: Telegram polling и отправка напоминаний.
~~~

### Внешний API и модель

Для генерации ответов используется **Groq API**, совместимый с OpenAI Chat Completions.

- Сервис: Groq.
- Базовый URL: https://api.groq.com/openai/v1.
- Модель задаётся через LLM_MODEL; значение шаблона .env.example: openai/gpt-oss-120b.
- Ключ API передаётся через переменную окружения LLM_API_KEY.
- Адрес API задаётся через LLM_BASE_URL.

Пример локальной конфигурации:

~~~env
TELEGRAM_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_API_KEY=YOUR_GROQ_API_KEY
LLM_MODEL=openai/gpt-oss-120b
POSTGRES_USER=alfa
POSTGRES_PASSWORD=CHANGE_ME_TO_A_LONG_RANDOM_PASSWORD
POSTGRES_DB=alfa
MINIAPP_URL=https://skilly-miniapp-new.vercel.app
MINIAPP_ORIGINS=https://skilly-miniapp-new.vercel.app
PLATFORM_URL=https://kurs.alfabank.ru/
UTM_SUFFIX=
DEFAULT_TZ=Europe/Moscow
QUIET_START=21
QUIET_END=9
MAX_REMINDERS_PER_USER=8
MAX_REMINDERS_PER_DAY=3
KB_MIN_SCORE=0.005
MAT_MIN_SCORE=0.005
EMBED_MODEL=
EMBED_DIM=1536
EMBED_BASE_URL=
EMBED_API_KEY=
~~~

Ключ не хранится в исходном коде: приложение читает его из переменной окружения при запуске. Для эмбеддингов предусмотрены EMBED_MODEL, EMBED_BASE_URL и EMBED_API_KEY; они необязательны, если отдельная модель эмбеддингов не используется.

## 5. Входные данные

Решение использует:
1. **Сообщение пользователя** — вопрос, запрос рекомендации или параметры напоминания.
2. **Профиль пользователя** — сведения о бизнесе, опыте, налоговом режиме, цели и часовом поясе.
3. **Историю диалога** — контекст для продолжения консультации.
4. **Каталог материалов** — названия, описания, темы, типы доступа и ссылки из данных кейса.
5. **Базу знаний** — текстовые фрагменты материалов для поиска и подготовки ответов.
6. **События и напоминания** — действия пользователя и параметры уведомлений.

Поиск обращается к PostgreSQL-схеме kb, в том числе к функциям kb.search_chunks и kb.search. Пользовательские таблицы приложения создаются из app/schema.sql. **Для полноценного поиска необходимо заранее загрузить и подготовить данные кейса в схеме kb: создание таблиц приложения само по себе не наполняет базу знаний.**

Данные кейса разрешено использовать только для выполнения задания. Не добавляйте исходные выгрузки, их копии, закрытые материалы или персональные данные в открытый репозиторий и общедоступные хранилища.

## 6. Требования и переменные окружения

Для запуска необходимы:
- Docker Engine и Docker Compose plugin;
- токен Telegram-бота от BotFather;
- ключ Groq API (или другого совместимого провайдера при соответствующей настройке);
- подготовленная база знаний в PostgreSQL для проверки ответов и рекомендаций;
- HTTPS-домен для запуска Mini App через Telegram.

Для локальной разработки Mini App дополнительно нужны Node.js и npm.

### Подключение Telegram-бота

1. Откройте @BotFather в Telegram.
2. Создайте бота командой /newbot или используйте уже созданного бота.
3. Скопируйте выданный Bot Token.
4. Вставьте токен в локальный .env в переменную TELEGRAM_TOKEN.
5. Для Mini App укажите HTTPS-адрес в MINIAPP_URL и соответствующий origin в MINIAPP_ORIGINS, а также настройте домен Mini App в Telegram.

Бот получает обновления через long polling. При запуске через сервис api polling и фоновый цикл напоминаний запускаются внутри FastAPI lifecycle. Не запускайте одновременно api и bot с одним токеном.

**Важно:** присланные в переписке Telegram Bot Token, Groq API Key и пароль PostgreSQL следует считать скомпрометированными: немедленно отзовите/перевыпустите токен бота и API-ключ, смените пароль БД. Рабочие секреты не добавляются в Git. В репозитории находятся только безопасные заглушки в .env.example; реальные значения храните исключительно в локальном .env и секретах хостинга.

## 7. Запуск через Docker одной командой

После заполнения .env и подготовки базы знаний выполните из корня проекта:

~~~bash
docker compose up --build -d db api
~~~

Команда собирает образ приложения, запускает PostgreSQL 16 и FastAPI. Сервис api также запускает Telegram polling и фоновую отправку напоминаний. PostgreSQL ожидает готовности по healthcheck.

**Важно:** не запускайте одновременно api и bot с одним Telegram-токеном — оба процесса используют long polling. Если нужен только Telegram-бот без HTTP API, используйте вместо основной команды:

~~~bash
docker compose up --build -d db bot
~~~

### Проверка запуска

~~~bash
docker compose ps
docker compose logs -f api
~~~

Проверка API:

~~~bash
curl http://localhost:8081/health
~~~

Ожидаемый ответ:

~~~json
{"ok":true,"service":"alpha-api"}
~~~

Остановка контейнеров без удаления данных:

~~~bash
docker compose down
~~~

Данные PostgreSQL хранятся в именованном Docker volume pgdata. Не используйте docker compose down -v, если необходимо сохранить базу данных.

| Сервис | Порт контейнера | Порт хоста |

### Основные HTTP-маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | /health | Проверка доступности API |
| GET | /api/me | Данные пользователя Telegram и профиль |
| GET | /api/profile | Получение профиля |
| PUT | /api/profile | Обновление профиля |
| POST | /api/chat | Сообщение ИИ-помощнику |
| GET | /api/history | История диалога |
| GET | /api/materials | Получение и поиск материалов |
| POST | /api/material-click | Регистрация открытия материала |
| GET | /api/reminders | Список напоминаний |

Пользовательские маршруты Mini App требуют заголовок X-Telegram-Init-Data со значением Telegram initData. Сервер проверяет подпись и срок действия данных.

## 9. Пошаговый сценарий проверки для экспертов

Проверку рекомендуется проводить на отдельном тестовом Telegram-профиле.

### Шаг 1. Запуск
1. Создать локальный .env на основе .env.example.
2. Указать Telegram Bot Token, LLM API key и параметры PostgreSQL.
3. Убедиться, что база знаний кейса загружена в схему kb.
4. Выполнить docker compose up --build -d db api.
5. Проверить docker compose ps и http://localhost:8081/health.
6. Открыть бота в Telegram и отправить /start.

**Ожидаемый результат:** API проходит health-check, бот отвечает на команду запуска.

### Шаг 2. Вопрос, ответ на который есть в базе
1. Задать конкретный вопрос по теме, присутствующей в базе знаний.
2. Проверить содержание ответа и предложенные материалы.

**Ожидаемый результат:** ответ основан на найденных фрагментах; подходящий материал предлагается при наличии релевантного результата.

### Шаг 3. Неоднозначный вопрос
1. Задать вопрос, для ответа на который не хватает важной детали.
2. Ответить на уточнение.

**Ожидаемый результат:** помощник запрашивает недостающий контекст и продолжает консультацию.

### Шаг 4. Вопрос вне базы знаний
1. Задать вопрос, по которому в базе нет подтверждающей информации.
2. Проверить реакцию помощника.

**Ожидаемый результат:** помощник сообщает об отсутствии точной информации и не выдаёт догадку за факт.

### Шаг 5. Персонализация
1. Сообщить стадию бизнеса, сферу, налоговый режим, опыт и цель.
2. Задать вопрос или попросить подборку материалов.
3. Повторить запрос после сохранения профиля.

**Ожидаемый результат:** профиль сохраняется и учитывается в последующих сценариях.

### Шаг 6. Рекомендации
1. Попросить подобрать материалы под конкретную бизнес-задачу.
2. Проверить соответствие материалов запросу и корректность ссылок.
3. Убедиться, что закрытое содержание платных материалов не раскрывается.

**Ожидаемый результат:** пользователь получает релевантные доступные материалы с корректными ссылками из каталога.

### Шаг 7. Напоминания
1. Попросить создать разовое напоминание на ближайшее будущее.
2. Указать дату и время и проверить подтверждение создания.
3. Дождаться отправки.
4. Создать повторяющееся напоминание.
5. Изменить его периодичность или отключить.

**Ожидаемый результат:** напоминание сохраняется, отправляется в заданное время и управляется пользователем.

### Шаг 8. Mini App
1. Открыть Mini App через Telegram.
2. Проверить загрузку интерфейса.
3. Просмотреть и изменить профиль.
4. Отправить сообщение помощнику.
5. Открыть материалы.
6. Создать или отключить напоминание.

**Ожидаемый результат:** Mini App взаимодействует с API, а пользовательские запросы проходят проверку Telegram initData.

## 10. Известные ограничения

- Качество ответов зависит от полноты, структуры и актуальности базы знаний.
- Для ответов и рекомендаций необходимы подготовленные данные и функции PostgreSQL-схемы kb; в одном репозитории может не быть исходной выгрузки кейса.
- Внешний LLM API требует действующего ключа, доступности сервиса и корректного имени модели.
- При отключении или недоступности LLM API генерация ответов не выполняется.
- Качество рекомендаций зависит от метаданных каталога, поисковых оценок и корректности ссылок.
- Эмбеддинги не включены автоматически: для их использования нужно настроить переменные окружения и подготовить совместимые данные.
- Mini App должен быть доступен через HTTPS и открываться из Telegram.
- Для работы Telegram-сценариев необходим действующий Bot Token и исходящее подключение к Telegram API.
- Налоговые и юридические ответы не заменяют официальные источники и консультации специалистов. Налоговые даты нужно проверять по актуальным данным ФНС.
- Напоминания отправляются в рамках настроенных ограничений и часового пояса.

## 11. Безопасность

- Рабочие токены, ключи и пароли передаются только через локальные переменные окружения.
- Файл .env не должен попадать в Git; для настройки используется .env.example.
- Исходные выгрузки кейса, закрытые материалы и персональные данные не публикуются.
- Во внешние API передаются только необходимые фрагменты, без персональных данных и закрытых материалов, не предназначенных для сторонних сервисов.
- Для платных материалов не раскрывается подробное содержание; используется только предоставленная ссылка на материал или покупку.
- API Mini App проверяет подписанные данные Telegram initData.

## 12. Дальнейшее развитие

- Расширение и регулярное обновление базы знаний.
- Улучшение гибридного поиска по ключевым словам и эмбеддингам.
- Контроль качества ответов на тестовом наборе вопросов.
- Измерение релевантности рекомендаций на контрольных сценариях.
- Персональные образовательные маршруты с учётом прогресса.
- Аналитика переходов к материалам, повторных обращений и возврата к обучению.

Для оценки возврата пользователей можно анализировать обезличенные события: открытия рекомендованных материалов, переходы на платформу, повторные обращения и возвращение к обучению после напоминаний. Эффект следует проверять сравнением показателей до и после внедрeния.
